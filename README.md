# Sentiro

AI-powered market & crypto sentiment dashboard. Build a personal watchlist of
stocks and crypto; a scheduled job pulls live price data and recent news,
then uses an LLM to generate a sentiment score and a plain-English narrative
("why is this moving") per ticker.

Full spec: [docs/Sentiro_Project_Spec.md](docs/Sentiro_Project_Spec.md)

## Stack

- **Frontend**: React + TypeScript (Vite), Tailwind CSS, Recharts, Framer Motion
- **Backend**: FastAPI (Python), SQLAlchemy, APScheduler
- **Database + Auth**: Supabase (Postgres + built-in auth)
- **LLM**: Google Gemini (free tier, `gemini-flash-latest`)
- **Market data**: `yfinance` (stocks) + CoinGecko (crypto) — no keys required
- **News**: Marketaux (primary) + NewsAPI (fallback)

**Critical design constraint**: external API calls (price, news, LLM) only
ever happen inside the scheduled background job, never on a page load or API
request — the frontend and read endpoints only ever touch cached data in
Postgres. This keeps everything on free tiers.

## Local development

### Backend

```bash
cd backend
python -m venv venv
./venv/Scripts/activate   # or source venv/bin/activate on macOS/Linux
pip install -r requirements.txt
cp .env.example .env      # fill in the values (see below)
uvicorn app.main:app --reload --port 8000
```

### Frontend

```bash
cd frontend
npm install
cp .env.example .env      # fill in the values
npm run dev                # http://localhost:5173
```

## Environment variables

`backend/.env`:

| Var | Where to get it |
|---|---|
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_KEY` | Supabase project → Settings → API |
| `DATABASE_URL` | Supabase project → Settings → Database → Connection string (session pooler, port 5432) |
| `GEMINI_API_KEY` | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) — free, no card |
| `MARKETAUX_API_KEY` | [marketaux.com](https://www.marketaux.com) — free tier |
| `NEWSAPI_KEY` | [newsapi.org](https://newsapi.org) — free dev tier (optional fallback) |
| `CORS_ORIGINS` | comma-separated frontend origin(s), e.g. `http://localhost:5173` |
| `INSIGHT_REFRESH_MINUTES` | scheduler interval, e.g. `45` |

`frontend/.env`:

| Var | Where to get it |
|---|---|
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | same Supabase project as backend |
| `VITE_API_URL` | backend base URL, e.g. `http://localhost:8000` |

## Manually triggering a refresh

Insights are normally only generated by the scheduled APScheduler job
(every `INSIGHT_REFRESH_MINUTES`). To run one refresh cycle immediately
(useful right after deploying, or for local testing):

```bash
cd backend
./venv/Scripts/python.exe scripts/refresh_now.py
```
